# Архітектура AI-агента

## Призначення

AI-агент автоматизує початкове створення та перевірку кросплатформного C++-проєкту
за схемою **CMake + GoogleTest/CTest**. Він вирішує такі проблеми:

- створює однакову структуру проєкту без ручного налаштування файлів;
- генерує мінімальну програму `hello` та тест `BasicAddition`;
- налаштовує окремий каталог збірки, щоб вихідні файли не змішувалися з
  артефактами компіляції;
- запускає локальну збірку й тести та показує помилки на відповідному етапі;
- готує GitHub Actions workflow для автоматичної збірки і тестування у CI;
- дозволяє повторно виконувати команди без руйнування вже створеного проєкту.

## Компоненти та етапи

Оркестратор керує трьома спеціалізованими skills:

1. **`project-scaffold`** — створює або доповнює структуру C++-проєкту:
   `CMakeLists.txt`, каталог вихідного коду, каталог тестів і `.gitignore`.
2. **`build-and-test`** — конфігурує CMake, компілює ціль `hello` та запускає
   GoogleTest через CTest.
3. **`github-actions`** — генерує workflow у
   `.github/workflows/` для повторення локальної збірки й тестування в GitHub
   Actions.

Типовий порядок роботи:

```text
init
  ├─ git-init
  ├─ create-project
  ├─ create-build
  ├─ create-actions
  └─ check
```

Етапи виконуються послідовно, оскільки кожен наступний використовує результат
попереднього.

## Доступні commands

| Command | Призначення |
|---|---|
| `init` | Запускає повний оркестровий сценарій від ініціалізації до перевірки. |
| `git-init` | Перевіряє Git-репозиторій, створює його за потреби та готує базові правила ігнорування. |
| `create-project` | Створює C++-код `hello`, CMake-конфігурацію та тест `BasicAddition` на GoogleTest/CTest. |
| `create-build` | Створює каталог `build/`, конфігурує CMake і виконує локальну збірку. |
| `create-actions` | Створює GitHub Actions workflow для CMake, GoogleTest/CTest і перевірки збірки. |
| `check` | Запускає підсумкову перевірку: наявність файлів, збірку `hello`, тест `BasicAddition` і workflow. |

Команди мають бути ідемпотентними: повторний запуск оновлює лише потрібні
керовані файли та не видаляє користувацький код.

## Дані між етапами

Оркестратор передає між skills структурований контекст проєкту:

- корінь репозиторію та платформу;
- назви цілей CMake (`hello`, тестова ціль) і шлях до вихідних файлів;
- обраний генератор CMake та параметри конфігурації;
- абсолютний або відносний шлях до `build/`;
- статус попереднього етапу, код завершення і короткий текст помилки;
- список створених або перевірених файлів;
- результати компіляції та CTest, зокрема статус `BasicAddition`;
- шлях до GitHub Actions workflow і його стан готовності.

Таким чином, `build-and-test` отримує структуру, підготовлену
`project-scaffold`, а `github-actions` може використати ті самі команди
конфігурації, збірки й тестування. Фінальний `check` отримує всі результати й
формує підсумок для користувача.

## Обробка помилок

Після кожного етапу оркестратор перевіряє код завершення та валідність
переданих даних. Якщо команда або skill завершується зі збоєм:

1. оркестратор зберігає діагностику та назву невдалого етапу;
2. припиняє виконання наступних етапів;
3. повідомляє користувачу команду, що завершилася помилкою, і доступний
   контекст для виправлення;
4. не маскує помилку успішним результатом і не переходить до фінального
   статусу `готово`.

Після виправлення причини користувач може повторно запустити `init` або окрему
команду. Ідемпотентність етапів дає змогу продовжити роботу без видалення
наявних результатів.
